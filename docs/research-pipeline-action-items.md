## P1 — small, high-value, code already half-there

### [Done] 1. Wire durable memory into SceneBuilder

**Objective:** `MemoryHost.render_memory_context`
(`tools/research/memory_host.py:118`) was built for scene injection but
`tools/research/scene_builder.py` never imports `memory_host` — it is dead in
the production flow. Add an optional memory-injection step to
`SceneBuilder.build_scene` so the assembled scene includes the durable-memory
summary when a memory store is present, within the existing token budget
(`build_scene` at `scene_builder.py:34-62`).

**Done when:** a pytest in `tools/research/__tests__/` shows a scene built with
a populated `.durable_memory.json` contains the rendered memory context and
still respects `--max-tokens`; the test fails on the unmodified code; full
`make test-py` is green.

**Boundaries:** no new CLI dependencies; injection must be a no-op when no
memory store exists; do not redesign the scene format beyond the memory slot.

### [Done] 2. Implement CitationEngine text-alignment check

**Objective:** `tools/research/citation_engine.py` validates file existence
(`:86`) and line-range bounds (`:93-115`) but never compares the citation's
link label / quoted text against the actual source lines, despite the module
docstring (`:7`) claiming it does. Implement the third check: verify the
cited text aligns with the content at the referenced line range.

**Done when:** `verify_text` flags a citation whose label/quote does not match
the referenced lines in the source file; new tests cover match, mismatch, and
tolerable-whitespace cases and fail before the change; `make test-py` green.

**Boundaries:** define "alignment" conservatively (normalized substring /
fuzzy-whitespace match) and document the tolerance in the docstring; do not
change the accepted link format in `LINK_PATTERN`.

### [Done] 3. Enforce the citation section on cards in the validator

**Objective:** the card contract requires a final
`源码与文档引用 (Source Citation):` section with `[path#Ls-Le](file://...)`
links, but nothing in `tools/research/anki_card_validator.py` checks it.
Add a detector that rejects cards missing the section or with malformed
citation links (the canonical format is generated by
`search_chunks.format_file_link`, `:151-154`).

**Done when:** `validate_cards` rejects a card without the citation section and
a card with a malformed link; existing valid fixtures still pass; new tests
fail before the change; `make test-py` green.

**Boundaries:** validator change only; do not wire `CitationEngine` into the
import path in the same PR. Check existing imported cards' format first — if
the current corpus violates the new rule, gate it as warning-first and note
that in the PR body.

### [Done] 4. Generalize the question/answer mismatch detector

**Objective:** `_question_matches_answer`
(`tools/research/anki_card_validator.py:255-263`) is a single hardcoded
heuristic for one specific card; all other fronts return True. Either
generalize it into a real front/back consistency check (e.g. key-term overlap
between question and answer), or — if a general heuristic proves too noisy —
remove the special case and document the decision.

**Done when:** either (a) the generalized detector catches at least the
existing mismatch fixture class plus a synthetic one, with tests, or (b) the
hardcoded special case is deleted and the spec/skill note the detector's
removal. `make test-py` green either way.

**Boundaries:** false positives are worse than no check — if (a), the detector
must not reject any card in the current valid test fixtures.

## P2 — larger features, need a design pass first

### [Done] 5. Dense vector index + true RRF for the hybrid indexer

**Objective:** `tools/research/search_chunks.py` is BM25-only;
`reciprocal_rank_fusion` (`:126-141`) currently fuses multiple per-token BM25
passes (`--rrf` at `:198-202`), not lexical + vector lists as
`docs/research-agent-spec.md` §2.3 intends. Add a dense embedding index over
the chunk manifest and make `--rrf` fuse BM25 and vector rankings.

**Done when:** `--rrf` demonstrably fuses two heterogeneous rankings (unit
test with stubbed embedding scores); embedding index build is reproducible and
cached; `make test-py` green.

**Boundaries:** no new heavyweight runtime dependency without surfacing it
first — prefer a local embedding approach or an explicit, discussed dependency
addition (AGENTS.md non-negotiable #6 binds unattended routines; an interactive
agent may add one but must call it out in the PR body). Keep pure-BM25 the
default mode.

### [Done] 6. Scene slots: primary/prerequisite distinction + lab-code slot

**Objective:** the scene formula (spec §3.1) distinguishes R_primary, C_prereq,
and A_code; `SceneBuilder` emits one flat BM25 ranking. Extend scene assembly
to reserve slots: top-ranked chunk as primary reading, distinct prerequisite
material, and an explicit code/topology chunk (`.p4`, `.py`, `.gns3`) when one
ranks in the candidate set.

**Done when:** a scene built over a mixed corpus contains a labeled code slot
when a code chunk is relevant, and tests cover presence/absence of each slot;
`make test-py` green.

**Boundaries:** stay within the existing token-budget mechanism; coordinate
with item 1 (memory slot) if both are in flight — do not merge them into one PR.

### [Done] 7. Working Memory buffer in MemoryHost

**Objective:** `tools/research/memory_host.py` implements only the durable
store; spec §4 has a short-term Working Memory layer (active-turn buffer with
session-end summarization into the durable store). Implement it.

**Done when:** a session buffer records turns, and an explicit
flush/summarize path folds it into `.durable_memory.json`; tests cover
record → flush → persisted; `make test-py` green.

**Boundaries:** the buffer is in-process state plus explicit flush — do not add
a daemon or background writer.

### [Done] 8. Mastery-score computation engine

**Objective:** `record_mastery` (`memory_host.py:52-81`) stores a
caller-supplied score verbatim (clamped to [0,1]); nothing computes proficiency
from performance. Add a computation path (e.g. rolling average / decay over
`session_history`) so scores can be derived rather than asserted.

**Done when:** a caller can record raw performance events and the stored
mastery score is computed from them; tests show the score moving correctly
across a scripted sequence; `make test-py` green.

**Boundaries:** keep the existing caller-supplied-score API working (the CLI
`--record --score` path depends on it); add the computed path alongside.

### [Done] 9. CurriculumService (prerequisite graph)

**Objective:** no prerequisite dependency graph across `cs231`–`cs234` modules

**Done when:** the graph covers the four course dirs with real prerequisite

**Boundaries:** start with a hand-authored graph informed by the courseware —

### [Done] 10. SynthesisService (cross-course analysis scaffolding)

**Objective:** no cross-course comparative-analysis code exists (spec §2.2).

**Done when:** a CLI accepts two queries and emits one scene with chunks from

**Boundaries:** the synthesis prose itself stays with the host agent (Layer 4

### [Done] 11. Automated Batch Runner

**Objective:** all entry points are one-shot synchronous CLIs; spec §2.1 wants
an asynchronous job scheduler for large-scale processing (e.g. course-wide

existing CLIs over a manifest of queries.

**Done when:** a batch spec file drives N sequential/queued CLI invocations
with per-job status capture; tests use stubbed commands; `make test-py` green.

**Boundaries:** keep it stdlib-only and single-machine; no external queue or
scheduler daemon.

### [Done] 12. ResourceGovernor

**Objective:** token budgeting lives inline in `scene_builder.py:34-62`;
execution timeouts and read-only-FS enforcement exist nowhere (spec §2.3).
Extract a `ResourceGovernor` component owning token budgets and add

**Done when:** scene building uses the governor's budget API (behavior
unchanged), and at least one CLI path enforces a configurable timeout; tests
green.

**Boundaries:** behavior-preserving refactor plus the timeout; do not attempt
filesystem sandboxing in the first PR.
