Multiple Periods MPD Support
Can the current MP4Client handle multiple Periods in an MPD ﬁle? Well, in my
opinion, the answer is positive. At ﬁrst, we can look into the mpd.h ﬁle. Because
this head ﬁle deﬁned the structure of the MPD, which will be applied in mpd.c,
dash client.c and so on. The mpd.h ﬁle is in this directory:
~/gpac/include/gpac/internal/mpd.h
In this ﬁle, we can see a structure called GF MPD. Inside this structure, it has an
attribution called periods, which stands for a list of periods:
GF_List *periods;
At this point, we’ve known that a MPD can consist multiple periods.
Now we can go and see how dash client.c support multiple period MPD. We
can ﬁnd the dash client.c at:
~/gpac/src/media_tools/dash_client.c
This program uses a function called gf list get to handle the period list.
The function gf list get is imported from:
~/gpac/include/gpac/list.h
In this head ﬁle, we can see its usage clearly. This function is deﬁned as follows:
void*gf_list_get(GF_List *ptr, u32 position);
It helps to get an item from the list given its position. So back to the dash client.c
ﬁle, for example, there is a function called gf dash seek groups:
static void gf_dash_seek_groups(GF_DashClient*dash,
Double seek_time, Bool is_dynamic)
Inside this function, we can look at the following code snippet:
for (i=0; i<dash->active_period_index; i++) {
GF_MPD_Period *period = gf_list_get(dash->mpd->periods,
dash->active_period_index-1);
dur += period->duration/1000.0;
}

Assign Tile Quality Levels
In this section, we will focus on the following ﬁle:
~/gpac/src/media_tools/dash_client.c
In this ﬁle, we are focusing on modifying the following function:
static void dash_do_rate_adaptation(GF_DashClient *dash,
GF_DASH_Group*group, int adaptation_set_num)
As we can see from the instruction of this assignment, diﬀerent value of models
refers to diﬀerent representations.
At ﬁrst, in this function, we get the initial representation by getting the active
representation inside the group:
rep = gf_list_get(group->adaptation_set->representations,
group->active_rep_index);
As we can observe from the source code, the function gets new representation
by assigning a new index of representation:
new_rep = gf_list_get(group->adaptation_set->representations,
(u32)new_index);
So, to get diﬀerent representations, we only need to change the value of new index.
If we want to get the representation of speciﬁc model, we only need to change the
new index to the model value.
As we can see, the new index is initialized by:
new_index = 0;
So the default model is 0. In this case, we only need to change the new index
to model - 1 to switch the representation:
new_index = group->adaptation_set->model - 1;
